CatherIs Argus {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

1. Prove the cluster enforces the NetworkPolicies, after every install and upgrade:

     helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

2. Open the UI. {{ if .Values.auth.saml.enabled }}Single sign-on is on, at {{ .Values.auth.publicUrl }}.{{ else }}There is no single sign-on, so keep the UI private.{{ end }} To reach it
   without an ingress, forward the web Service to this machine's loopback, so the browser keeps
   the Secure session cookie:

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "argus.fullname" . }}-web 8080:8080
     # then http://localhost:8080, as {{ .Values.admin.username }}

3. Schema migrations run in the Job {{ include "argus.fullname" . }}-migrate-*; api and the scheduler
   start once it has finished. Run Jobs carry the label app.kubernetes.io/component=run:

     kubectl -n {{ .Release.Namespace }} get jobs -l app.kubernetes.io/instance={{ .Release.Name }}

The namespace must carry pod-security.kubernetes.io/enforce=restricted and hold nothing but Argus.
{{- if not .Values.admissionPolicy.enabled }}

WARNING: the admission policy is off (admissionPolicy.enabled=false). Nothing checks the Jobs the
scheduler creates: a compromised scheduler can start any image as the service account
{{ include "argus.serviceAccount" (dict "root" . "name" "run") }}, with its cloud identity, and read any Secret in this namespace.
{{- end }}
{{- if not .Values.networkPolicy.enabled }}

WARNING: the NetworkPolicies are off (networkPolicy.enabled=false). Every pod can reach Postgres,
every pod can reach the API and set the client address it records, and every pod has a route
out. `helm test` has no probe to run.
{{- end }}
{{- if not .Values.resourceQuota.enabled }}

WARNING: the ResourceQuota is off: nothing bounds how many pods and Jobs the scheduler can start.
{{- end }}
{{- if or .Values.api.autoscaling.enabled .Values.web.autoscaling.enabled }}

NOTE: autoscaling is on. It needs metrics-server, which EKS does not install by default:
`kubectl get hpa -n {{ .Release.Namespace }}` shows <unknown> targets without it.
{{- end }}
{{- if .Values.web.ingress.enabled }}

NOTE: the Ingress is on ({{ .Values.web.ingress.host }}). It must serve HTTPS: the session cookie is
Secure, so over plain HTTP nobody can sign in. It must also be the only proxy in front of web, or
Argus records the proxy's address as the client's. To check that web
sees real addresses, sign in with a wrong password and read `kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "argus.fullname" . }}-web`:
the line must start with your address, not the ingress's.
{{- if eq (get .Values.web.ingress.annotations "alb.ingress.kubernetes.io/scheme") "internet-facing" }}

{{- if .Values.auth.saml.enabled }}
{{- if .Values.auth.localSignIn }}

WARNING: this ALB is internet-facing and password sign-in is still on (auth.localSignIn), with no
second factor. Once SSO works, turn it off, or restrict who can reach the ALB.
{{- end }}
{{- else }}

WARNING: this ALB is internet-facing, and single sign-on is off (auth.saml), so there is no second

{{- end }}

WARNING: the NetworkPolicies are off, so any pod that reaches web can choose the client address

{{- end }}
{{- end }}
